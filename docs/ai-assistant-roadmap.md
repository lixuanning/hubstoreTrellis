# 百果 AI 助手 · 产品能力蓝图实施规划

> **文档目的**: 基于《百果AI助手 · 产品能力蓝图》（2026-07 产品规划），将蓝图转化为 StoreHub 4 仓库的渐进式实施路线图。
>
> **状态**: 规划阶段，不一蹴而就，按业务优先级逐步落地。

---

## 一、蓝图核心结构

```
门店业务闭环: 获取知识 → 落地执行 → 管理提效 → 营销获客 → 经营复盘
                                                          ↓ (复盘反哺)

入口: 百果秘书 App（首屏悬浮 AI 机器人统一入口）

5 大能力域:
  ① 知识服务 AI  ── 学知识，知万物
  ② 门店执行 AI  ── 落标准，门店动作在线
  ③ 工作助理 AI  ── 提效率，统一待办中枢
  ④ 营销增长 AI  ── 做营销，门店增长引擎
  ⑤ 经营决策 AI  ── 促复盘，数据驱动经营

底座: 果品知识大模型 + 智能问数 + 盈利诊断 + 陈列指导方案 + 营销素材库 + 培训资料/知鸟 + 消息集成（企微·OA·应用消息·待办）
```

---

## 二、实施阶段划分

### Phase 1 — MVP 入口（已完成基础）

**目标**: 先把"统一入口"和最基础的对话能力打通

| 模块 | 状态 | 实现说明 |
|------|------|---------|
| 百果秘书 AI 机器人入口 | 待 | uniapp 首页悬浮组件（当前 demo 已验证 API 链路） |
| 智能问答助手（基础版） | 待 | ai 端对接 LLM，最简单的 RAG |
| 消息集成基础 | 部分 | uniapp 已有消息公告弹窗（messageService） |

**涉及端**：
- ai: 新建 `chat/` 模块，对接 LLM
- serverless: 新建 `chat/postMessage.post.ts` 等
- uniapp: 新建 `ai-assistant/` 模块，浮动机器人组件

---

### Phase 2 — 知识服务 AI ①

**目标**: 学知识、知万物

| 模块 | 涉及 |
|------|------|
| 果品知识助手 | ai: 知识库 + 向量化；web: H5 知识详情页 |
| 企业知识助手 | ai: 企业文档 RAG |
| 产品功能助手 | ai: 产品手册检索 |
| 培训助手 | 现有知鸟系统对接 |

**技术依赖**：
- ai 需引入 LangChain + 向量数据库（已有知识）
- web 需要新增知识管理 H5

---

### Phase 3 — 门店执行 AI ②

**目标**: 落标准，门店动作在线

| 模块 | 涉及 |
|------|------|
| AI 巡店助手 | 现有 ai-verify 模块增强 + LLM 解读 |
| AI 陈列助手 | ai: 新模块，对接图片识别 + 标准模板 |

**技术依赖**：
- 复用现有 `ai-store-api/src/ai-verify/`
- 复用现有 `ai-store-api/src/vfm-tag/`（AI 识别）

---

### Phase 4 — 工作助理 AI ③

**目标**: 提效率，统一待办中枢

| 模块 | 涉及 |
|------|------|
| AI 待办管理 | uniapp: 待办中心；ai: 待办智能拆分 |
| 消息总结 | ai: 企微消息 LLM 摘要 |
| 待办聚合 | 现有 messageService 扩展 |
| 主动提醒策略 | ai: cron 任务 + 智能判断 |
| 一般/重要/紧急事区分 | ai: 模型判断优先级 |

---

### Phase 5 — 营销增长 AI ④

**目标**: 做营销，门店增长引擎

| 模块 | 涉及 |
|------|------|
| AI 营销助手 | ai: 营销文案生成 + 素材推荐 |
| AI 唤报助手 | ai: 客户唤回策略生成 |

**技术依赖**：
- 需对接营销素材库（web 中新增 `marketing-assets/`）

---

### Phase 6 — 经营决策 AI ⑤

**目标**: 促复盘，数据驱动经营

| 模块 | 涉及 |
|------|------|
| 智能问数助手 | ai: NL2SQL |
| AI 经营诊断与日报 | ai: 数据分析 + 自动生成日报 |
| AI 经营异常提醒 | ai: 异常检测 + 预警 |

**技术依赖**：
- 复用现有 ai-verify / warning 模块
- 需引入业务数据中台对接

## 三、底座建设（横向支撑）

底座不是单独 Phase，贯穿所有阶段，**优先于业务模块实施**：

| 底座组件 | 优先级 | 涉及端 |
|---------|--------|--------|
| 果品知识大模型 | P0 | ai |
| 智能问数 | P1 | ai |
| 盈利诊断 | P2 | ai |
| 陈列指导方案 | P2 | ai |
| 营销素材库 | P3 | web |
| 培训资料/知鸟 | P2 | ai + 第三方对接 |
| 消息集成（企微/OA/应用消息/待办） | P0 | serverless（已有基础） |

## 四、权限体系（贯穿所有能力域）

按蓝图要求：

| 层级 | 说明 |
|------|------|
| **权限隔离** | 按角色控制可访问的 AI 功能 |
| **角色权限管理** | 门店管理员可访问所有 AI 功能，非门店管理员访问受限 |
| **统一权限中心** | 权限集中配置管理 |

**实施位置**：
- ai: RBAC 模块扩展（已有 `src/rbac/`）
- serverless: 权限校验中间件
- uniapp: 角色切换与权限提示

```
  └─ Phase 5 营销增长 AI
  └─ Phase 6 经营决策 AI

  └─ 权限体系扩展
  └─ 12 项 AI 应用的逐个深化
```

## 六、技术债务与准备工作

实施前需评估的：

1. **ai-store-api 是否引入 LangChain** — 当前已有自研 AI 识别（vfm-tag、ai-verify），需评估是否替换或并存
2. **向量数据库选型** — 知识库需要向量检索，候选：Milvus / Qdrant / pgvector
3. **LLM 选型** — 通义千问 / 文心 / 自研果品模型
4. **多端消息协议** — 5 大能力域都涉及消息集成，需统一消息协议
5. **uniapp 机器人入口定位** — 首页悬浮 vs TabBar 入口
